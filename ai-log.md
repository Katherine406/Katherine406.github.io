# AI Prompts & Vibe Coding Process Reflection

## AI-Assisted Design & Development Workflow

To accelerate the development and iteration of UniBuddy, we adopted an AI-assisted Vibe Coding process that combined human-centered design methods with rapid AI-supported prototyping and frontend refinement.

Our workflow integrated:
- HTML / CSS / JavaScript implementation
- React + Vite frontend development
- GitHub Pages deployment
- Figma prototype design
- Cursor AI-assisted coding and restructuring
- ChatGPT for design reasoning, reflection writing, and usability interpretation

Rather than replacing design decisions, AI primarily functioned as a co-iteration tool for:
- brainstorming,
- restructuring,
- technical refinement,
- and rapid content generation.

---

# AI Prompts Used Throughout Development

## 1. Project Direction

> “Help us define the core problem, target users, and value proposition for a campus navigation app for XJTLU freshmen and visitors.”

### Purpose
Used during the early ideation phase to clarify:
- the main navigation frustrations,
- who the system should support,
- and what unique value UniBuddy could provide compared to existing map tools.

### Outcome
Helped establish:
- freshmen and external visitors as primary users,
- emotional comfort + exploration as key goals,
- and the concept of playful campus navigation.

---

## 2. Feature Prioritization

> “Create a Must/Should/Could feature list for our UniBuddy project based on human-centered design principles.”

### Purpose
Used to define MVP scope and avoid feature overload.

### Outcome
Separated:
- essential navigation features,
- optional personalization,
- and future exploratory functions such as mystery routes and gamified interactions.

---

## 3. Interview Analysis

> “Summarize our interview notes into key pain points and map them into design opportunities.”

### Purpose
Used after user interviews and informal discussions.

### Outcome
Converted raw notes into structured insights including:
- unclear building recognition,
- stressful first-week navigation,
- and lack of emotional engagement in existing campus maps.

---

## 4. Questionnaire Insights

> “Turn our questionnaire results into 3 key strengths and 3 critical gaps of current campus navigation tools.”

### Purpose
Used to transform quantitative feedback into clearer evaluation findings.

### Outcome
Helped identify:
- strong demand for visual guidance,
- low satisfaction with existing route clarity,
- and missing onboarding support for new students.

---

## 5. Gap Analysis

> “Compare official campus map apps and social discovery apps, and explain where UniBuddy can create unique value.”

### Purpose
Used to position UniBuddy within existing solutions.

### Outcome
Revealed that:
- official map systems focused only on functionality,
- while social discovery apps lacked navigation precision.

UniBuddy aimed to combine:
- accurate route guidance,
- emotional reassurance,
- and exploratory campus storytelling.

---

# Vibe Coding Process: AI & Tools Reflection

## Development Approach

We adopted an AI-assisted Vibe Coding process to accelerate iteration speed while maintaining a human-centered design workflow.

The process combined:
- rapid prototyping,
- modular frontend development,
- iterative testing,
- and AI-assisted restructuring.

Instead of building the entire system linearly, development evolved through:
1. idea exploration,
2. prototype experimentation,
3. page-level implementation,
4. modular component refinement,
5. usability testing,
6. and iterative redesign.

---

# How AI Was Used

## Content & Documentation
- Drafting and polishing portfolio sections
- Structuring evaluation discussions
- Generating technical reflections
- Rewriting academic content into clearer formats

## Frontend Iteration
- Refactoring HTML/CSS structures
- Improving navigation hierarchy
- Testing alternative timeline layouts
- Optimizing modular page organization

## Usability Evaluation
- Transforming raw user notes into structured insights
- Summarizing pilot test findings
- Generating reflection frameworks
- Supporting SUS interpretation

## Design Exploration
- Exploring multiple prototype directions quickly
- Generating alternative interaction ideas
- Comparing layout structures before implementation

---

# What Worked Well

## Faster Iteration Speed
AI-assisted drafting significantly reduced the time needed for:
- layout experimentation,
- portfolio writing,
- and frontend restructuring.

## Modular Development
Section-by-section refinement improved:
- maintainability,
- debugging efficiency,
- and collaborative editing.

## Improved Communication
AI restructuring helped make:
- user-testing findings,
- design rationales,
- and evaluation summaries
clearer and more academically structured.

## Rapid Idea Exploration
Multiple UI and wording alternatives could be tested quickly before committing to implementation.

---

# Challenges & Limitations

## Visual Consistency Problems
Some AI-generated interface suggestions:
- conflicted with the existing design language,
- or introduced inconsistent spacing and styling patterns.

Manual redesign was still required.

## Generic Wording
Automatically generated reflections sometimes became:
- overly broad,
- repetitive,
- or disconnected from the actual project context.

Significant human rewriting was needed.

## Technical Constraints
AI could not fully solve:
- GitHub Pages hosting instability,
- routing refresh problems,
- asset-loading failures,
- or deployment configuration issues.

These still required manual debugging and engineering knowledge.

## Design Judgment Still Required
AI accelerated production,
but final decisions regarding:
- usability,
- interaction quality,
- emotional experience,
- and accessibility
still depended on human evaluation and testing evidence.

---

# Reflection for Future Iterations

AI proved highly effective for:
- speed,
- drafting,
- restructuring,
- and rapid experimentation.

However, successful design outcomes still relied on:
- user-centered reasoning,
- iterative testing,
- and human editorial control.

For future iterations, we plan to:
- define stricter design tokens earlier,
- standardize reusable component rules,
- improve documentation consistency,
- and establish clearer UI constraints before implementation.

This would reduce:
- redesign overhead,
- style inconsistency,
- and integration conflicts during later development stages.
